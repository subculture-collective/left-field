# Correction and Address Activation Implementation Plan

> **For agentic workers:** Execute this plan task-by-task. Recommended path:
> dispatch a fresh subagent per task, review each result with `review-quality`,
> then continue. Steps use checkbox (`- [ ]`) syntax for tracking. This document
> is an implementation plan, not an approval or activation record: correction
> intake and address lookup remain disabled until their signed,
> environment-bound approval packages verify.

**Goal:** Make the existing correction workflow and Census-backed address lookup privacy-preserving, operationally maintainable, and cryptographically gated, while keeping both features dark by default and throughout all blocked external reviews.

**Architecture:** After the finance/election proof migration, add immutable `0007_correction_privacy_lifecycle.sql`, which separates deletable sensitive payloads from controlled-retention operational metadata and ledger records. Put both public surfaces behind a root-owned, verified feature-gate file; `disabled` renders no collection UI, loads no collection bundle, and exposes no usable API. A root-only verifier writes the gate file only after validating a two-signature, environment-bound package. Correction activation excludes Census. Address uses an independent address-canary package first; only after 14/30-day expiry evidence may a new address-enable package be signed. Address lookup remains a tightly isolated Census egress path; correction moderation remains isolated from release mutation and from payload cleanup.

**Tech Stack:** Next.js 16/React 19/TypeScript, Zod, PostgreSQL 16/PostGIS with Drizzle, Vitest, Playwright/Axe, systemd, Nginx, root-owned JSON gate material, detached signatures, HMAC rotation tooling, and existing Census resolver/admission roles.

---

## Non-negotiable release state and blockers

- Default and deployed state is `disabled` for **both** corrections and address lookup. `canary` and `enabled` are accepted only from the root-owned verified gate, never directly from application environment variables.
- `disabled` means: no correction or address form, no correction/address client bundle or client fetch, no token endpoint, and a finite disabled API response that reads neither body nor sensitive headers. The informational pages must carry no collection controls.
- No task below activates either feature. The only permitted runtime states before signed approval are `disabled`; address's approved, short canary is additionally constrained below.
- The following are explicit **BLOCKED gates**, not blank fields to fill in later: correction requires its own security/operations package and correction evidence; address requires written Census vendor/egress disposition, its own address-canary package, complete host/proxy/CDN/WAF/log/APM/session-replay inventory and redaction evidence, primary/replica/archive/vendor backup retention and deletion evidence, then 14/30-day expiry evidence and a new address-enable package. Missing applicable evidence keeps that feature `disabled`.
- Retention policy to encode and test: correction payloads `pending` 90 days, `in_review` 90 days, `accepted` 30 days, `rejected` 30 days, `incorporated` 30 days; `queued` has a hard maximum of 180 days; non-sensitive metadata has controlled deletion at 2 years unless legal hold; rate/idempotency buckets follow their approved short TTLs; backups expire within 30 days. Legal hold pauses destruction only for the specifically held record and records why/when in the deletion ledger.
- Address lookup remains disabled until the Census vendor/egress review passes. Never capture request bodies, full URLs (including Census query URLs), database bind values, normalized address, coordinates, or client address data in logs, traces, errors, metrics labels, support capture, or APM.

## Execution order and activation boundary

1. Complete Tasks 1–6 as small, independently reviewable commits; each commit must remain safe with both modes disabled.
2. Deploy only the dark artifact, migration, root verifier, edge configuration, and maintenance timers. Confirm `/run/dsa-seats/feature-gates.json` is root-owned and declares disabled for both features.
3. Do **not** advance based on this plan, code review, CI, or a filled example manifest. Correction activation uses a correction-only package and explicitly excludes Census. Address activation first uses a separate address-canary package; an external security signer and distinct external operations signer must approve each exact verified package after its applicable BLOCKED evidence is supplied.
4. After the separately authorized address canary, force disabled, run required post-expiry searches at 14 days for logs and 30 days for backups, preserve only non-sensitive evidence, then sign a new address-enable package (with a distinct manifest, gates, and mode). Any failure, missing result, expiry, or kill exercise leaves that feature disabled.
